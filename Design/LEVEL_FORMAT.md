# Формат уровня

Уровень — это JSON-файл в `Assets/_Project/Resources/Levels/<id>.json`. Игра читает все файлы из этой папки и сортирует их по `order`. Сцены и префабы не нужны: `LevelBuilder.cs` строит уровень из текста при запуске.

## Поля

| Поле | Тип | Что это |
|---|---|---|
| `id` | string | Совпадает с именем файла без `.json`, например `03_peshchera` |
| `order` | int | Порядковый номер уровня в игре (1, 2, 3…) |
| `title` | string | Заголовок на экране: `"Акт III. Пещера сомнений"` |
| `act` | int | Номер акта |
| `awareness` | int 0..5 | Стадия прозрения шарика (см. `Design/GDD.md`) |
| `palette` | string | `meadow` · `cave` · `city` · `glitch` · `void` |
| `storyBeat` | string | Что сейчас происходит в душе шарика. Уходит в промпт нейросети, пишите 2–4 предложения от третьего лица |
| `goalHint` | string | Необязательная подсказка о цели |
| `final` | bool | Только у последнего уровня: там вместо `F` стоит рубильник `R` |
| `intro` | string[] | Реплики в начале уровня, по очереди. Каждая до 140 символов |
| `outro` | string[] | Реплики у выхода. В финальном уровне всё, кроме последней, звучит ДО рубильника, а последняя — после исчезновения мира |
| `lines` | `{x, text, mood}`[] | Реплики, которые срабатывают, когда шарик докатился до колонки `x` |
| `fragments` | string[] | Тексты «осколков кода» `*` по порядку: сверху вниз, слева направо |
| `grid` | string[] | ASCII-карта. Строка 0 — верх уровня. Все строки одной длины |

`mood` — одно из: `neutral happy scared angry sad awe pray dizzy suspicious determined glitch`.

## Легенда сетки

| Символ | Что это | Правила |
|---|---|---|
| `.` | пусто | |
| `#` | земля | верхний блок рисуется с травой/крышей автоматически |
| `=` | тонкая платформа | можно запрыгнуть снизу, можно стоять сверху |
| `S` | старт шарика | ровно один, на клетке над землёй |
| `F` | дверь-выход | ровно один (или `R`). Стоит на земле, занимает 1×2 клетки визуально |
| `R` | рубильник | только при `"final": true` |
| `K` | чекпоинт | стоит на земле. После смерти шарик появляется здесь |
| `*` | осколок кода | висит в воздухе на пути шарика, 0–3 штуки на уровень |
| `^` | ловушка «шипы» | стоит на земле (под ней `#` или `=`). Игрок выдвигает на 1.6 с |
| `C` | ловушка «пресс» | висит в воздухе, под ним ≥2 пустых клеток и пол. Падает, делает лепёшку |
| `T` | ловушка «люк» | часть пола, под ней пусто (яма). Открывается на 1.6 с |
| `W` | ловушка «вентилятор» | стоит на земле, дует вверх на 5 клеток |
| `J` | ловушка «пружина» | стоит на земле, подбрасывает шарик на ~8 клеток вверх |

## Физика: что шарик может

Константы синхронизированы в `Tools/levels/levellib.py` и `Assets/_Project/Scripts/Core/Tuning.cs`.

- Прыжок вверх: до **3 клеток**.
- Прыжок через яму на том же уровне: до **5 клеток** (безопасно проектировать **≤4**).
- Падение с **5+ клеток** превращает шарик в лепёшку: он не умирает, это смешно, используйте.
- Бездонная яма (нет пола до низа уровня) убивает, шарик появляется на последнем чекпоинте.
- Камера показывает примерно 20×11 клеток.

## Правила хорошего уровня

1. **Высота 12–16 строк, ширина 60–160 колонок.** Нижние 2–3 строки — «толща» земли.
2. **Путь идёт слева направо.** Инстинкт шарика тянет его к выходу, лабиринты он не любит (не больше 6 клеток назад).
3. **Каждая ловушка стоит на пути.** Игрок должен иметь шанс помешать, а шарик — шанс проскочить.
4. **Ритм:** спокойный участок → препятствие → «комедийная» ловушка → передышка с репликой → …
5. **Чекпоинт `K`** после каждого трудного участка, примерно каждые 30–40 колонок.
6. **Реплики `lines`** ставьте ПЕРЕД местом, к которому они относятся, за 2–4 колонки.
7. **Проверяйте:** `python3 Tools/levels/validate.py <файл>` должен выдавать `[OK]` без ошибок.
8. **Смотрите:** `python3 Tools/levels/render.py <файл> --path`, затем откройте `Design/previews/<id>.png`.
